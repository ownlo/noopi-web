# NOOPI (누피) UI Specification

## 1. 문서 목적

이 문서는 NOOPI 모바일 웹 Frontend의 화면, 사용자 흐름, 상태별 UI 및
사용자 행동 규칙을 정의한다.

구현 시 다음 문서를 함께 따른다.

-   `SERVICE_SPEC.md`
-   `GAME_SESSION_SPEC.md`
-   `REALTIME_SPEC.md`
-   `API_SPEC.md`
-   `games/LIAR_GAME_SPEC.md`

Frontend는 게임 규칙과 승패를 자체 판단하지 않는다. 서버가 반환한 현재
상태를 기준으로 화면을 렌더링한다.

------------------------------------------------------------------------

# 2. UI 기본 원칙

NOOPI의 핵심 문구는 다음과 같다.

> **게임은 사람끼리, 진행은 웹이.**

따라서 UI는 사용자가 계속 휴대폰 화면만 바라보게 만들지 않는다.

핵심 원칙:

1.  한 화면에는 현재 필요한 행동을 중심으로 보여준다.
2.  현재 Player가 할 수 없는 행동 버튼은 보여주지 않는다.
3.  다른 Player의 행동이 필요한 경우 기다림 상태를 보여준다.
4.  역할, 제시어 등 비밀 정보는 명확하게 분리한다.
5.  게임 설명보다 실제 진행 상태를 우선한다.
6.  오프라인 대화가 필요한 단계에서는 화면 개입을 최소화한다.
7.  서버 상태가 Source of Truth다.
8.  새로고침/재접속 후에도 현재 게임 단계로 복구한다.
9.  모바일 세로 화면을 기본으로 설계한다.
10. 가입/로그인 없이 최대한 빠르게 게임을 시작할 수 있어야 한다.

------------------------------------------------------------------------

# 3. 기본 화면 규격

MVP는 모바일 웹을 우선한다.

권장 콘텐츠 영역:

``` text
width: 100%
max-width: 430px
```

데스크톱에서는 모바일 화면이 중앙에 배치될 수 있다.

화면은 다음 영역을 기본으로 한다.

``` text
┌────────────────────────┐
│ Header                 │
│ NOOPI / Room 정보      │
├────────────────────────┤
│                        │
│ Main Content           │
│                        │
├────────────────────────┤
│ Primary Action         │
└────────────────────────┘
```

게임 중에는 불필요한 네비게이션을 최소화한다.

------------------------------------------------------------------------

# 4. 공통 디자인 방향

NOOPI는 가볍고 장난스러운 게임 서비스의 느낌을 지향한다.

기본 방향:

-   Dark Navy 기반 배경
-   Neon Purple / Blue 계열 강조
-   둥근 카드와 버튼
-   귀여운 캐릭터/이모지 활용 가능
-   중요한 결과는 큰 타이포그래피와 간단한 애니메이션으로 강조
-   터치 영역은 모바일 사용성을 고려해 충분히 크게 구성
-   긴 설명보다 짧고 직관적인 문구 사용

정확한 디자인 토큰은 Frontend 구현 단계에서 별도로 정의할 수 있다.

# 6. 홈 화면

## 목적

서비스 진입 후 즉시 Room 생성 또는 참가로 이동한다.

## 표시

``` text
NOOPI

게임은 사람끼리,
진행은 웹이.

[ 방 만들기 ]

[ 방 참가하기 ]
```

## 행동

### 방 만들기

닉네임/성별 입력 화면으로 이동한다.

### 방 참가하기

Room Code 입력 화면으로 이동한다.

로그인/회원가입 버튼은 제공하지 않는다.

------------------------------------------------------------------------

# 7. Room Code 입력 화면

## 표시

``` text
방 코드를 입력해주세요

[ A B 1 2 C D ]

[ 다음 ]
```

QR 링크로 진입한 경우 이 화면을 건너뛸 수 있다.

## 다음

Room Code가 유효하면 닉네임/성별 입력 화면으로 이동한다.

Room이 없거나 종료된 경우 오류 메시지를 표시한다.

------------------------------------------------------------------------

# 8. 닉네임 / 성별 입력 화면

Room 생성과 Room 참가 모두 사용한다.

## 표시

``` text
게임에서 사용할 이름을 정해주세요

닉네임
[ 종윤                 ]

성별
[ 남자 ] [ 여자 ]

[ 시작하기 ]
```

Room 참가 흐름에서는 버튼 문구를 `[ 참가하기 ]`로 사용할 수 있다.

## 규칙

-   닉네임은 Room 단위 Player 정보다.
-   성별도 Room 단위 Player 정보다.
-   성별 값은 `MALE`, `FEMALE`.
-   같은 Room에서 중복 닉네임은 허용하지 않는다.
-   이전에 사용한 닉네임/성별이 로컬에 있다면 초기값으로 제안할 수 있다.

------------------------------------------------------------------------

# 9. Room 생성 완료 / 초대 화면

방장에게 Room Code와 QR을 제공한다.

## 표시 예시

``` text
친구들을 초대해보세요!

        [ QR ]

방 코드

AB12CD

[ 코드 복사 ]

참가자 1명

🐱 종윤 👑

친구들을 기다리는 중...
```

Player가 참가하면 실시간으로 목록을 갱신한다.

## 방장 행동

필요한 인원이 모이면 게임 선택으로 이동할 수 있다.

``` text
[ 게임 선택하기 ]
```

다른 참가자는 게임 선택 버튼을 볼 수 없다.

------------------------------------------------------------------------

# 10. 참가자 로비 화면

## 공통 표시

-   Room Code
-   현재 참가자 목록
-   방장 표시
-   연결 상태
-   현재 인원

예시:

``` text
NOOPI ROOM

AB12CD

🐱 종윤 👑
🐰 예은
🐧 철수
🐻 민수

4명이 모였어요!
```

## 일반 참가자

``` text
방장이 게임을 고르는 중이에요 👀
```

## 방장

활성 GameSession이 없다면:

``` text
[ 게임 선택하기 ]
```

------------------------------------------------------------------------

# 11. 게임 선택 화면

방장 전용 화면이다.

MVP에서 활성화된 게임만 표시한다.

예시:

``` text
무슨 게임을 할까요?

┌────────────────────┐
│ 😈 라이어 게임      │
│                    │
│ 3~12명             │
│ 제시어를 숨긴       │
│ 라이어를 찾아보세요 │
└────────────────────┘
```

비방장은 다음 상태를 표시한다.

``` text
방장이 게임을 고르고 있어요
```

------------------------------------------------------------------------

# 12. 라이어 게임 설정

방장에게만 설정 UI를 제공한다.

## 표시

``` text
😈 라이어 게임

카테고리를 골라주세요

[ 🎲 랜덤 ]
[ 🍔 음식 ]
[ 🌍 장소 ]
[ ... ]

참가자 4명
라이어 1명

[ 게임 시작 ]
```

카테고리 목록은 Backend API에서 받아온다.

Frontend에 카테고리를 하드코딩하지 않는다.

`RANDOM`도 서버 응답에 포함된 가상 카테고리로 취급한다.

라이어 수를 설정하는 UI는 없다.

라이어는 항상 1명이다.

------------------------------------------------------------------------

# 13. 게임 시작 대기

방장이 게임을 생성했지만 아직 시작하지 않은 상태에서는 참가자에게 게임
정보를 보여줄 수 있다.

``` text
😈 라이어 게임

카테고리
🍔 음식

4명 참가

방장이 게임을 시작할 때까지
기다려주세요.
```

방장:

``` text
[ 게임 시작 ]
```

------------------------------------------------------------------------

# 14. 역할 확인 화면

`ROLE_REVEAL` 단계.

이 화면은 개인별 비밀 정보 화면이다.

## 시민

``` text
당신은

🙂 시민입니다

제시어

🍔 떡볶이

라이어에게 들키지 않게
이야기해보세요.

[ 확인했어요 ]
```

## 라이어

``` text
당신은

😈 라이어입니다

제시어를 모르는 사람은
당신뿐이에요.

정체를 들키지 마세요!

[ 확인했어요 ]
```

라이어에게 `keyword`를 절대 표시하지 않는다.

## 확인 완료 후

본인이 이미 확인했다면 버튼을 제거한다.

``` text
다른 사람들을 기다리고 있어요

3 / 4 확인 완료
```

가능하면 참가자별 확인 상태를 표시한다.

``` text
종윤 ✓
예은 ✓
철수 ✓
민수 ...
```

역할 정보는 절대 다른 Player 항목에 표시하지 않는다.

------------------------------------------------------------------------

# 15. 첫 발언자 공개

모든 Player가 역할을 확인하면 서버가 선정한 첫 발언자를 전체 화면에
보여준다.

예시:

``` text
첫 번째로 말할 사람은...

🐧 철수!

철수부터 제시어에 대해
한마디씩 이야기해주세요.
```

잠시 후 DISCUSSION 화면으로 자연스럽게 이어질 수 있다.

자동 전환 또는 사용자 확인 방식은 Frontend 구현에서 선택할 수 있다.

------------------------------------------------------------------------

# 16. DISCUSSION 화면

실제 추리는 사람들끼리 오프라인에서 진행한다.

따라서 화면은 최대한 단순하게 유지한다.

## 일반 참가자

``` text
🕵️ 라이어를 찾아보세요

서로 이야기하면서
수상한 사람을 찾아보세요!

첫 발언자
🐧 철수

방장이 투표를 시작할 때까지
추리해주세요.
```

버튼 없음.

## 방장

``` text
🕵️ 라이어를 찾아보세요

충분히 이야기했나요?

[ 투표 시작 ]
```

방장만 투표 시작 버튼을 볼 수 있다.

------------------------------------------------------------------------

# 17. 투표 화면

투표는 비밀투표다.

## 기본 규칙

-   본인에게 투표할 수 없다.
-   한 라운드에 한 번만 투표할 수 있다.
-   제출 후 변경할 수 없다.
-   다른 Player의 투표 대상은 볼 수 없다.
-   현재 득표수는 투표 완료 전 공개하지 않는다.

## 투표 전

``` text
누가 라이어 같나요?

한 명을 선택해주세요.

○ 🐱 종윤
○ 🐧 철수
○ 🐻 민수

[ 투표하기 ]
```

본인은 후보에서 제외한다.

## 제출 확인

실수 방지를 위해 최종 제출 전에 간단한 확인 UI를 사용할 수 있다.

``` text
🐧 철수에게 투표할까요?

투표 후에는 바꿀 수 없어요.

[ 취소 ] [ 투표하기 ]
```

------------------------------------------------------------------------

# 18. 투표 완료 대기 화면

본인이 투표를 제출한 후 후보 선택 UI를 제거한다.

``` text
투표 완료! ✓

다른 사람을 기다리고 있어요

3 / 5 완료

종윤 ✓
예은 ✓
철수 ...
민수 ✓
준호 ...
```

누가 누구에게 투표했는지는 표시하지 않는다.

------------------------------------------------------------------------

# 19. 투표 결과 화면

모든 투표가 완료되면 후보별 총 득표수만 공개한다.

예시:

``` text
🔥 투표 결과

🐱 종윤
████ 4표

🐧 철수
█ 1표

가장 많은 지목을 받은 사람은...

🐱 종윤
```

다음 정보는 절대 표시하지 않는다.

``` text
종윤 → 철수
예은 → 종윤
```

즉, `누가 누구에게 투표했는지`는 게임 종료 후에도 공개하지 않는다.

------------------------------------------------------------------------

# 20. 동률 결과

최다 득표자가 여러 명이면 동률을 알린다.

``` text
⚡ 동률!

🐱 종윤  2표
🐧 철수  2표

두 사람 중
다시 투표해주세요.
```

재투표에서는 서버가 지정한 동률 후보만 표시한다.

본인이 동률 후보라면 본인을 제외한 선택 가능한 후보만 표시한다.

재투표에서도 다시 동률이면 동일한 흐름을 반복한다.

재투표 횟수 제한은 없다.

서버가 랜덤으로 한 명을 지목하는 UI/연출은 만들지 않는다.

------------------------------------------------------------------------

# 21. 최종 지목 연출

단독 최다 득표자가 결정되면 결과를 강조한다.

``` text
가장 많은 지목을 받은 사람은...

🐱 종윤
```

이후 서버 판정 결과를 보여준다.

연출을 위해 짧은 딜레이나 애니메이션을 사용할 수 있지만, 실제 상태를
임의로 변경해서는 안 된다.

------------------------------------------------------------------------

# 22. 시민을 지목한 경우

최종 지목자가 라이어가 아니면 라이어 승리다.

``` text
🐱 종윤의 정체는...

🙂 시민이었습니다!

라이어 검거 실패 😈

실제 라이어는

🐰 예은!

제시어
🍔 떡볶이

😈 라이어 승리
```

게임은 `FINISHED` 상태다.

------------------------------------------------------------------------

# 23. 라이어를 지목한 경우

최종 지목자가 실제 라이어라면 바로 시민 승리로 처리하지 않는다.

``` text
🐰 예은의 정체는...

😈 라이어였습니다!

하지만 아직 끝이 아니에요.

라이어가 제시어를 맞히면
라이어가 승리합니다.
```

이후 `LIAR_GUESS` 단계로 이동한다.

------------------------------------------------------------------------

# 24. 라이어 제시어 추측 --- 라이어 화면

실제 라이어에게만 입력 UI를 제공한다.

``` text
마지막 기회! 😈

제시어가 무엇이었을까요?

[ 답을 입력해주세요      ]

[ 정답 제출 ]
```

제출 전:

``` text
이 답으로 제출할까요?

제출 후에는 바꿀 수 없어요.
```

한 번 제출한 답은 변경할 수 없다.

------------------------------------------------------------------------

# 25. 라이어 제시어 추측 --- 시민 화면

시민에게 입력창이나 제출 버튼을 절대 표시하지 않는다.

``` text
라이어의 마지막 기회...

🐰 예은이
제시어를 추측하고 있어요.

잠시만 기다려주세요 👀
```

------------------------------------------------------------------------

# 26. 최종 결과 --- 시민 승리

라이어가 제시어를 맞히지 못한 경우:

``` text
🎉 시민 승리!

라이어
🐰 예은

제시어
🍔 떡볶이

라이어의 답
피자 ❌
```

------------------------------------------------------------------------

# 27. 최종 결과 --- 라이어 승리

라이어가 제시어를 맞힌 경우:

``` text
😈 라이어 승리!

라이어
🐰 예은

제시어
🍔 떡볶이

라이어의 답
떡볶이 ✓
```

시민을 잘못 지목한 경우에는 라이어의 답 영역을 표시하지 않는다.

------------------------------------------------------------------------

# 28. 게임 종료 후 행동

Room은 유지된다.

## 방장

``` text
[ 같은 게임 다시하기 ]

[ 다른 게임 고르기 ]

[ 방 종료 ]
```

같은 게임 다시하기:

-   새로운 GameSession 생성
-   라이어 재선정
-   제시어 재선정
-   첫 발언자 재선정
-   기존 Player 유지

다른 게임 고르기:

게임 선택 화면으로 이동한다.

## 일반 참가자

``` text
방장이 다음 게임을 고르고 있어요 🎮
```

------------------------------------------------------------------------

# 29. 재접속 / 새로고침 UI

페이지 새로고침 또는 WebSocket 재접속 후 클라이언트는 `/state`를
조회한다.

``` text
연결 복구
   ↓
GET /state
   ↓
현재 phase 확인
   ↓
해당 화면 렌더링
```

예:

``` text
ROLE_REVEAL → 역할 화면
DISCUSSION  → 추리 화면
VOTING      → 투표 또는 투표 완료 대기
REVOTING    → 재투표
LIAR_GUESS  → 라이어/시민별 화면
FINISHED    → 결과
```

이미 투표한 Player는 새로고침해도 다시 투표할 수 있는 UI를 보여주지
않는다.

------------------------------------------------------------------------

# 30. 연결 끊김 표시

다른 Player가 일시적으로 연결을 잃으면 참가자 목록에 상태를 표시할 수
있다.

``` text
🐱 종윤
🐰 예은
🐧 철수  연결 끊김
🐻 민수
```

즉시 Room에서 제거하지 않는다.

게임 진행을 막을 정도로 장시간 연결이 끊긴 경우에만 방장에게 제외 기능을
제공한다.

``` text
🐧 철수
연결이 끊겼어요.

[ 현재 게임에서 제외 ]
```

해당 버튼은 서버가 제외 가능한 상태라고 판단한 경우에만 표시한다.

------------------------------------------------------------------------

# 31. 방장 변경

방장이 변경되면 전체 클라이언트가 새로운 방장 정보를 반영한다.

``` text
👑 새로운 방장

🐰 예은
```

새 방장에게만 게임 선택/시작/투표 시작 등 Host 전용 UI가 나타난다.

------------------------------------------------------------------------

# 32. 로딩 상태

API 요청 중에는 동일 행동의 중복 실행을 방지한다.

예:

``` text
[ 게임 시작 중... ]
```

``` text
[ 투표 제출 중... ]
```

버튼은 요청 완료 전까지 비활성화한다.

전체 화면 Blocking Loader는 꼭 필요한 경우에만 사용한다.

------------------------------------------------------------------------

# 33. 오류 UI

사용자가 이해할 수 있는 짧은 메시지를 표시한다.

예:

``` text
이미 투표했어요.
```

``` text
지금은 투표할 수 없어요.
```

``` text
방을 찾을 수 없어요.
```

상태 충돌 오류가 발생하면 `/state`를 다시 조회하여 서버 상태와 화면을
동기화하는 것을 우선한다.

개발용 오류 코드나 stack trace를 사용자에게 노출하지 않는다.

------------------------------------------------------------------------

# 34. Empty / Invalid Room

존재하지 않는 Room:

``` text
방을 찾을 수 없어요 🥲

방 코드를 다시 확인해주세요.

[ 홈으로 ]
```

종료된 Room:

``` text
이미 종료된 방이에요.

[ 홈으로 ]
```

------------------------------------------------------------------------

# 35. 현재 Player가 할 수 있는 행동만 표시

NOOPI UI의 핵심 규칙이다.

예:

``` text
방장
→ 게임 선택 버튼 O

일반 참가자
→ 게임 선택 버튼 X
→ "방장이 게임을 고르는 중" 표시
```

``` text
투표 전
→ 투표 UI O

투표 완료
→ 투표 UI X
→ 기다림 UI
```

``` text
라이어
→ 최종 제시어 입력 O

시민
→ 입력 X
→ 라이어 기다림 UI
```

단, 버튼을 숨기는 것은 보안 수단이 아니다. Backend에서도 반드시 권한을
검증한다.

------------------------------------------------------------------------

# 36. 비밀 정보 UI 규칙

다음 정보는 개인 화면에서 특별히 주의한다.

### 역할

본인 역할만 표시한다.

### 제시어

시민에게만 표시한다.

### 다른 Player의 역할

게임 종료 전 표시하지 않는다.

### 투표

누가 누구에게 투표했는지 표시하지 않는다.

### 득표수

투표 진행 중 표시하지 않는다.

투표 라운드 종료 후 후보별 최종 득표수만 표시한다.

# 37. WebSocket 이벤트와 UI

WebSocket 이벤트는 화면 변경 신호로 사용한다.

대표 흐름:

``` text
PLAYER_JOINED
→ 참가자 목록 갱신

HOST_CHANGED
→ Host UI 갱신

GAME_STARTED
→ /state 동기화
→ ROLE_REVEAL

ROLE_CHECKED
→ 확인 완료 인원 갱신

DISCUSSION_STARTED
→ 첫 발언자/토론 UI

VOTE_STARTED
→ 투표 UI

PLAYER_VOTED
→ 완료 인원 갱신

VOTE_RESULT
→ 투표 결과

REVOTE_STARTED
→ 재투표 UI

LIAR_GUESS_STARTED
→ 라이어: 입력 UI
→ 시민: 대기 UI

GAME_FINISHED
→ /state
→ 최종 결과
```

이벤트 payload만 믿고 전체 게임 상태를 재구성하지 않는다.

필요한 경우 `/state`를 다시 조회한다.

# 41. 최종 UI 구현 원칙

NOOPI Frontend는 다음 질문을 기준으로 화면을 결정한다.

``` text
1. 지금 게임이 어느 단계인가?
2. 나는 누구인가?
3. 나는 방장인가?
4. 나는 현재 GameSession 참가자인가?
5. 내가 이미 필요한 행동을 했는가?
6. 지금 내가 실제로 할 수 있는 행동은 무엇인가?
```

그 결과:

> **현재 Player가 지금 해야 할 것만 보여준다.**

이 원칙을 모든 화면의 최우선 기준으로 사용한다.
