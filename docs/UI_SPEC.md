# NOOPI (누피) UI Specification

## 1. 문서 목적

이 문서는 NOOPI 모바일 웹 Frontend의 화면, 사용자 흐름, 상태별 UI 및
사용자 행동 규칙을 정의한다.

구현 시 다음 문서를 함께 따른다.

-   `SERVICE_SPEC.md`
-   `GAME_SESSION_SPEC.md`
-   `REALTIME_SPEC.md`
-   `API_SPEC.md`
-   `games/LIAR_GAME_SPEC.md`
-   `games/BLIND_GAME_SPEC.md`
-   `games/MAFIA_GAME_SPEC.md`
-   `games/YUT_GAME_SPEC.md`
-   `games/PIG_GAME_SPEC.md`
-   `games/TOOTH_GAME_SPEC.md`

Frontend는 게임 규칙과 승패를 자체 판단하지 않는다. 서버가 반환한 현재
상태를 기준으로 화면을 렌더링한다.

------------------------------------------------------------------------

# 2. UI 기본 원칙

NOOPI의 핵심 문구는 다음과 같다.

> **게임은 사람끼리, 진행은 웹이.**

따라서 UI는 사용자가 계속 휴대폰 화면만 바라보게 만들지 않는다.

핵심 원칙:

1.  한 화면에는 현재 필요한 행동을 중심으로 보여준다.
2.  현재 Player가 할 수 없는 행동 버튼은 보여주지 않는다.
3.  다른 Player의 행동이 필요한 경우 기다림 상태를 보여준다.
4.  역할, 제시어 등 비밀 정보는 명확하게 분리한다.
5.  게임 설명보다 실제 진행 상태를 우선한다.
6.  오프라인 대화가 필요한 단계에서는 화면 개입을 최소화한다.
7.  서버 상태가 Source of Truth다.
8.  새로고침/재접속 후에도 현재 게임 단계로 복구한다.
9.  모바일 세로 화면을 기본으로 설계한다.
10. 가입/로그인 없이 최대한 빠르게 게임을 시작할 수 있어야 한다.

------------------------------------------------------------------------

# 3. 기본 화면 규격

MVP는 모바일 웹을 우선한다.

권장 콘텐츠 영역:

``` text
width: 100%
max-width: 430px
```

데스크톱에서는 모바일 화면이 중앙에 배치될 수 있다.

화면은 다음 영역을 기본으로 한다.

``` text
┌────────────────────────┐
│ Header                 │
│ NOOPI / Room 정보      │
├────────────────────────┤
│                        │
│ Main Content           │
│                        │
├────────────────────────┤
│ Primary Action         │
└────────────────────────┘
```

게임 중에는 불필요한 네비게이션을 최소화한다.

------------------------------------------------------------------------

# 4. 공통 디자인 방향

NOOPI는 가볍고 장난스러운 게임 서비스의 느낌을 지향한다.

기본 방향:

-   Dark Navy 기반 배경
-   Neon Purple / Blue 계열 강조
-   둥근 카드와 버튼
-   귀여운 캐릭터/이모지 활용 가능
-   중요한 결과는 큰 타이포그래피와 간단한 애니메이션으로 강조
-   터치 영역은 모바일 사용성을 고려해 충분히 크게 구성
-   긴 설명보다 짧고 직관적인 문구 사용

정확한 디자인 토큰은 Frontend 구현 단계에서 별도로 정의할 수 있다.

# 6. 홈 화면

## 목적

서비스 진입 후 즉시 Room 생성 또는 참가로 이동한다.

## 표시

``` text
NOOPI

게임은 사람끼리,
진행은 웹이.

[ 방 만들기 ]

[ 방 참가하기 ]
```

## 행동

### 방 만들기

닉네임/성별 입력 화면으로 이동한다.

### 방 참가하기

Room Code 입력 화면으로 이동한다.

로그인/회원가입 버튼은 제공하지 않는다.

------------------------------------------------------------------------

# 7. Room Code 입력 화면

## 표시

``` text
방 코드를 입력해주세요

[ 0 4 2 7 3 1 ]

[ 다음 ]
```

QR 링크로 진입한 경우 이 화면을 건너뛸 수 있다.

## 다음

Room Code가 유효하면 닉네임/성별 입력 화면으로 이동한다.

Room Code는 앞자리 `0`을 포함할 수 있는 정확히 6자리 숫자 문자열이다.
입력 화면은 모바일 숫자 키패드를 제공하고 숫자 이외의 문자를 허용하지 않는다.

Room이 없거나 종료된 경우 오류 메시지를 표시한다.

------------------------------------------------------------------------

# 8. 닉네임 / 성별 입력 화면

Room 생성과 Room 참가 모두 사용한다.

## 표시

``` text
게임에서 사용할 이름을 정해주세요

닉네임
[ 종윤                 ]

성별
[ 남자 ] [ 여자 ]

[ 시작하기 ]
```

Room 참가 흐름에서는 버튼 문구를 `[ 참가하기 ]`로 사용할 수 있다.

## 규칙

-   닉네임은 Room 단위 Player 정보다.
-   닉네임은 공백을 제외한 1글자 이상 5글자 이하다.
-   성별도 Room 단위 Player 정보다.
-   성별 값은 `MALE`, `FEMALE`.
-   같은 Room에서 중복 닉네임은 허용하지 않는다.
-   이전에 사용한 닉네임/성별이 로컬에 있다면 초기값으로 제안할 수 있다.

------------------------------------------------------------------------

# 9. Room 생성 완료 / 초대 화면

방장에게 Room Code와 QR을 제공한다.

## 표시 예시

``` text
친구들을 초대해보세요!

        [ QR ]

방 코드

042731

[ 코드 복사 ]

참가자 1명

🐱 종윤 👑

친구들을 기다리는 중...
```

Player가 참가하면 실시간으로 목록을 갱신한다.

## 방장 행동

필요한 인원이 모이면 게임 선택으로 이동할 수 있다.

``` text
[ 게임 선택하기 ]
```

다른 참가자는 게임 선택 버튼을 볼 수 없다.

------------------------------------------------------------------------

# 10. 참가자 로비 화면

## 공통 표시

-   Room Code
-   현재 참가자 목록
-   방장 표시
-   연결 상태
-   현재 인원

예시:

``` text
NOOPI ROOM

042731

🐱 종윤 👑
🐰 예은
🐧 철수
🐻 민수

4명이 모였어요!
```

## 일반 참가자

``` text
방장이 게임을 고르는 중이에요 👀
```

## 방장

활성 GameSession이 없다면:

``` text
[ 게임 선택하기 ]
```

방장은 본인을 제외한 참가자의 닉네임 옆 작은 내보내기 아이콘을 선택해
관리할 수 있다. 연결 상태 표시는 행 오른쪽의 동일한 위치를 유지한다. 아이콘을
선택하면 참가자 닉네임을 포함한 확인창을 표시하고, 확인 후 강제퇴장 요청을
보낸다. 요청 중에는 중복 실행을 막는다. 강제퇴장된 참가자는 홈 화면으로
이동한다. 일반 참가자에게는 이 행동을 표시하지 않으며 활성 GameSession이
있는 동안에는 제공하지 않는다.

------------------------------------------------------------------------

# 11. 게임 선택 화면

방장 전용 화면이다.

Room 화면 우측 상단에는 방장에게 대기 로비 이동 버튼과 Room 나가기 버튼을
함께 표시한다. 대기 로비 이동 버튼을 누르면 확인창을 표시하며, 확인 후
서버가 전체 참가자를 로비로 이동시킨다. 모든 참가자는
`방장이 모두를 대기실로 이동했어요.` 안내를 확인할 수 있어야 한다.

MVP에서 활성화된 게임만 표시한다.

지원 게임 목록 위에는 가로 스크롤 가능한 카테고리 필터를 표시한다.

``` text
[ 전체 ] [ 미니게임 ] [ 파티게임 ] [ 추리 ] [ 전략 ] [ 운빨 ] [ 개인전 ] [ 팀전 ]
```

- 최초 선택은 `전체`다.
- `전체`는 Frontend가 제공하는 가상 필터이며 API 카테고리에 포함되지 않는다.
- 나머지 카테고리 이름과 순서는 `GET /api/games`의
  `catalogCategories`를 그대로 사용한다.
- 카테고리를 선택하면 `catalogCategoryCodes`에 해당 코드가 포함된 활성 게임만
  표시한다.
- 하나의 게임이 여러 카테고리에 속할 수 있으므로 서로 다른 필터에서 같은
  게임이 표시될 수 있다.
- 필터 변경은 게임 목록 표시만 바꾸며 GameSession 설정에는 영향을 주지 않는다.
- 현재 카테고리에 활성 게임이 없으면 `이 카테고리에 준비된 게임이 없어요.`를
  표시한다.
- 필터는 실제 `button` 요소를 사용하고 선택 상태를 색상 외에도
  `aria-pressed`로 전달한다.
- 카테고리 행과 전체 화면에서 가로 스크롤이 생기지 않도록 하되, 카테고리
  행 자체의 가로 스크롤은 허용한다.

초기 소속은 다음과 같다.

``` text
미니게임  → 피그, 누피 콱!
파티게임  → 라이어 게임, 블라인드 게임, 마피아 게임, 윷놀이, 누피 콱!
추리      → 라이어 게임, 블라인드 게임, 마피아 게임
전략      → 윷놀이
운빨      → 윷놀이, 피그, 누피 콱!
개인전    → 블라인드 게임, 윷놀이, 피그, 누피 콱!
팀전      → 라이어 게임, 마피아 게임, 윷놀이
```

여기서 카탈로그 카테고리는 라이어 게임 시작 전 선택하는 제시어 카테고리와
다르다. 두 UI와 상태의 이름 및 용도를 혼용하지 않는다.

예시:

``` text
무슨 게임을 할까요?

┌────────────────────┐
│ 😈 라이어 게임      │
│                    │
│ 3~12명             │
│ 제시어를 숨긴       │
│ 라이어를 찾아보세요 │
└────────────────────┘

┌────────────────────┐
│ 🙈 블라인드 게임    │
│                    │
│ 2명                │
│ 상대의 제시어를 보고│
│ 내 제시어를 맞혀요  │
└────────────────────┘

┌────────────────────┐
│ 🕵️ 마피아 게임      │
│                    │
│ 4~12명             │
│ 밤의 단서를 모아    │
│ 마피아를 찾아보세요 │
└────────────────────┘

┌────────────────────┐
│ 🎲 윷놀이           │
│                    │
│ 2~4명              │
│ 윷을 던지고 말을    │
│ 먼저 완주해보세요   │
└────────────────────┘

┌────────────────────┐
│ 😼 누피 콱!          │
│                    │
│ 2~8명              │
│ 이빨을 누르고 꽝을  │
│ 피해 살아남으세요   │
└────────────────────┘
```

비방장은 다음 상태를 표시한다.

``` text
방장이 게임을 고르고 있어요
```

# 12. 라이어 게임 설정

방장에게만 설정 UI를 제공한다.

## 표시

``` text
😈 라이어 게임

카테고리를 골라주세요

[ 🎲 랜덤 ]
[ 🍔 음식 ]
[ 🌍 장소 ]
[ ... ]

참가자 4명
라이어 1명

[ 게임 시작 ]
```

카테고리 목록은 Backend API에서 받아온다.

Frontend에 카테고리를 하드코딩하지 않는다.

`RANDOM`도 서버 응답에 포함된 가상 카테고리로 취급한다.

라이어 수를 설정하는 UI는 없다.

라이어는 항상 1명이다.

------------------------------------------------------------------------

# 13. 게임 시작 대기

방장이 게임을 생성했지만 아직 시작하지 않은 상태에서는 참가자에게 게임
정보를 보여줄 수 있다.

``` text
😈 라이어 게임

카테고리
🍔 음식

4명 참가

방장이 게임을 시작할 때까지
기다려주세요.
```

방장:

``` text
[ 게임 시작 ]
```

# 14. 역할 확인 화면

`ROLE_REVEAL` 단계.

이 화면은 개인별 비밀 정보 화면이다.

## 시민

``` text
당신은

🙂 시민입니다

제시어

🍔 떡볶이

라이어에게 들키지 않게
이야기해보세요.

[ 확인했어요 ]
```

## 라이어

``` text
당신은

😈 라이어입니다

제시어를 모르는 사람은
당신뿐이에요.

정체를 들키지 마세요!

[ 확인했어요 ]
```

라이어에게 `keyword`를 절대 표시하지 않는다.

## 확인 완료 후

본인이 이미 확인했다면 버튼을 제거한다.

확인 완료는 역할 정보의 열람을 종료한다는 의미가 아니다. 대기 중에도
본인의 역할 카드를 유지하고, 시민에게는 본인의 제시어를 계속 표시한다.
라이어에게는 제시어를 표시하지 않는다.

``` text
다른 사람들을 기다리고 있어요

3 / 4 확인 완료
```

가능하면 참가자별 확인 상태를 표시한다.

``` text
종윤 ✓
예은 ✓
철수 ✓
민수 ...
```

역할 정보는 절대 다른 Player 항목에 표시하지 않는다.

------------------------------------------------------------------------

# 15. 발언 순서 공개

모든 Player가 역할을 확인하면 서버가 선정한 전체 발언 순서를 모든
Player에게 보여준다.

예시:

``` text
이번 게임의 발언 순서는...

1. 🐧 철수
2. 🐰 예은
3. 🐻 민수
4. 🐱 종윤

철수부터 제시어에 대해
한마디씩 이야기해주세요.
```

잠시 후 DISCUSSION 화면으로 자연스럽게 이어질 수 있다.

자동 전환 또는 사용자 확인 방식은 Frontend 구현에서 선택할 수 있다.

------------------------------------------------------------------------

# 16. DISCUSSION 화면

실제 추리는 사람들끼리 오프라인에서 진행한다.

따라서 화면은 최대한 단순하게 유지한다.

## 일반 참가자

``` text
🕵️ 라이어를 찾아보세요

서로 이야기하면서
수상한 사람을 찾아보세요!

발언 순서
1. 🐧 철수
2. 🐰 예은
3. 🐻 민수
4. 🐱 종윤

방장이 투표를 시작할 때까지
추리해주세요.
```

버튼 없음.

## 방장

``` text
🕵️ 라이어를 찾아보세요

충분히 이야기했나요?

[ 투표 시작 ]
```

방장만 투표 시작 버튼을 볼 수 있다.

## 내 역할 다시 보기

모든 Player는 `DISCUSSION` 화면에서 본인의 역할을 다시 확인할 수 있다.
기본 상태에서는 어깨너머 노출을 줄이기 위해 역할 정보를 가린다.

``` text
[ 🔒 내 역할 다시 보기 ]
```

버튼을 누르면 본인의 역할을 표시하고, 시민에게만 제시어를 함께 표시한다.
다시 가릴 수 있어야 한다. 라이어에게는 제시어를 절대 표시하지 않는다.

이 기능은 서버가 현재 Player에게 반환한 `myRole`과 `keyword`만 사용하며,
다른 Player의 역할 정보는 사용하지 않는다.

------------------------------------------------------------------------

# 17. 투표 화면

투표는 비밀투표다.

## 기본 규칙

-   본인에게 투표할 수 없다.
-   한 라운드에 한 번만 투표할 수 있다.
-   제출 후 변경할 수 없다.
-   다른 Player의 투표 대상은 볼 수 없다.
-   현재 득표수는 투표 완료 전 공개하지 않는다.

## 투표 전

``` text
누가 라이어 같나요?

한 명을 선택해주세요.

○ 🐱 종윤
○ 🐧 철수
○ 🐻 민수

[ 투표하기 ]
```

본인은 후보에서 제외한다.

## 제출 확인

실수 방지를 위해 최종 제출 전에 간단한 확인 UI를 사용할 수 있다.

``` text
🐧 철수에게 투표할까요?

투표 후에는 바꿀 수 없어요.

[ 취소 ] [ 투표하기 ]
```

------------------------------------------------------------------------

# 18. 투표 완료 대기 화면

본인이 투표를 제출한 후 후보 선택 UI를 제거한다.

``` text
투표 완료! ✓

다른 사람을 기다리고 있어요

3 / 5 완료

종윤 ✓
예은 ✓
철수 ...
민수 ✓
준호 ...
```

누가 누구에게 투표했는지는 표시하지 않는다.

------------------------------------------------------------------------

# 19. 투표 결과 화면

모든 투표가 완료되면 후보별 총 득표수만 공개한다.

예시:

``` text
🔥 투표 결과

🐱 종윤
████ 4표

🐧 철수
█ 1표

가장 많은 지목을 받은 사람은...

🐱 종윤
```

다음 정보는 절대 표시하지 않는다.

``` text
종윤 → 철수
예은 → 종윤
```

즉, `누가 누구에게 투표했는지`는 게임 종료 후에도 공개하지 않는다.

------------------------------------------------------------------------

# 20. 동률 결과

최다 득표자가 여러 명이면 동률을 알린다.

``` text
⚡ 동률!

🐱 종윤  2표
🐧 철수  2표

두 사람 중
다시 투표해주세요.
```

재투표에서는 서버가 지정한 동률 후보만 표시한다.

본인이 동률 후보라면 본인을 제외한 선택 가능한 후보만 표시한다.

재투표에서도 다시 동률이면 동일한 흐름을 반복한다.

재투표 횟수 제한은 없다.

서버가 랜덤으로 한 명을 지목하는 UI/연출은 만들지 않는다.

------------------------------------------------------------------------

# 21. 최종 지목 연출

단독 최다 득표자가 결정되면 결과를 강조한다.

``` text
가장 많은 지목을 받은 사람은...

🐱 종윤
```

이후 서버 판정 결과를 보여준다.

연출을 위해 짧은 딜레이나 애니메이션을 사용할 수 있지만, 실제 상태를
임의로 변경해서는 안 된다.

실제 라이어는

🐰 예은!

```

# 23. 라이어를 지목한 경우

최종 지목자가 실제 라이어라면 바로 시민 승리로 처리하지 않는다.

😈 라이어였습니다!

하지만 아직 끝이 아니에요.

라이어가 제시어를 맞히면

```

이후 `LIAR_GUESS` 단계로 이동한다.

# 24. 라이어 제시어 추측 --- 라이어 화면

실제 라이어에게만 입력 UI를 제공한다.

마지막 기회! 😈

제시어가 무엇이었을까요?

[ 답을 입력해주세요      ]

제출 전:

``` text

제출 후에는 바꿀 수 없어요.
```

한 번 제출한 답은 변경할 수 없다.

# 25. 라이어 제시어 추측 --- 시민 화면

``` text

🐰 예은이
제시어를 추측하고 있어요.

잠시만 기다려주세요 👀
```

# 28. 게임 종료 후 행동

Room은 유지된다.

## 방장

``` text
[ 같은 게임 다시하기 ]

[ 다른 게임 고르기 ]

[ 방 종료 ]
```

같은 게임 다시하기:

-   새로운 GameSession 생성
-   라이어 재선정
-   제시어 재선정
-   발언 순서 재선정
-   기존 Player 유지

다른 게임 고르기:

게임 선택 화면으로 이동한다.

## 일반 참가자

``` text
방장이 다음 게임을 고르고 있어요 🎮
```

# 29. 재접속 / 새로고침 UI

페이지 새로고침 또는 WebSocket 재접속 후 클라이언트는 `/state`를
조회한다.

``` text
연결 복구
   ↓
GET /state
   ↓
현재 phase 확인
   ↓
해당 화면 렌더링
```

예:

``` text
ROLE_REVEAL → 역할 화면
DISCUSSION  → 추리 화면
VOTING      → 투표 또는 투표 완료 대기
REVOTING    → 재투표
LIAR_GUESS  → 라이어/시민별 화면
FINISHED    → 결과
```

이미 투표한 Player는 새로고침해도 다시 투표할 수 있는 UI를 보여주지
않는다.

------------------------------------------------------------------------

# 30. 연결 끊김 표시

다른 Player가 일시적으로 연결을 잃으면 참가자 목록에 상태를 표시할 수
있다.

``` text
🐱 종윤
🐰 예은
🐧 철수  연결 끊김
🐻 민수
```

즉시 Room에서 제거하지 않는다.

연결 끊김 시간만으로 Player를 자동 퇴장시키거나 Room을 종료하지 않는다.
게임 진행이 어려운 참가자는 우측 상단의 나가기 버튼으로 직접 Room을
떠날 수 있다.

------------------------------------------------------------------------

# 31. Room 나가기

모든 Room 화면의 우측 상단에 나가기 버튼을 표시한다.

``` text
[ 나가기 아이콘  나가기 ]
```

일반 참가자가 나가면 해당 Player만 Room에서 제거하고 홈 화면으로
이동한다.

방장이 나가기를 선택하면 다음 내용을 확인한다.

``` text
방장이 나가면 방이 종료되고
모든 참가자가 홈으로 이동해요.

[취소] [나가기]
```

방장이 확인하면 Room을 종료하고 모든 참가자를 홈 화면으로 이동시킨다.

# 32. 로딩 상태

API 요청 중에는 동일 행동의 중복 실행을 방지한다.

예:

``` text
[ 게임 시작 중... ]
```

``` text

```

버튼은 요청 완료 전까지 비활성화한다.

전체 화면 Blocking Loader는 꼭 필요한 경우에만 사용한다.

## 피그 게임 화면 규칙

피그 게임 선택 카드에는 `2~6명` 개인전임을 표시한다. 목표 점수는 50점으로 고정하며 별도 설정 UI를 제공하지 않는다.

`PLAYING` 화면에는 목표 점수, 현재 턴 Player, Player별 총점·상태·확정 순위, 현재 턴 점수, 최근 주사위, 서버가 제공한 `1` 발생 확률을 표시한다. 현재 턴의 성공 횟수는 표시하지 않는다. 같은 숫자가 반복되어도 최근 결과를 그대로 표현하며, Client에서 다음 확률을 계산하지 않는다.

새 턴이 시작되어 현재 Player가 아직 주사위를 던지지 않은 상태에서는 직전 Player의 최근 결과와 관계없이 주사위 눈금을 표시하지 않는다. 직전 Player가 `1`을 던진 경우에도 결과 연출이 끝나면 새 턴의 주사위는 빈 상태로 돌아간다.

현재 Player에게는 `allowedActions`가 `ROLL`일 때 첫 던지기 또는 계속 던지기 버튼을, `STOP`일 때 멈추기 버튼을 제공한다. 다른 Player와 `FINISHED` Player에게는 행동 버튼 대신 진행 또는 관전 안내를 표시한다. mutation 중에는 두 행동을 모두 비활성화해 중복 요청을 막는다.

`BUSTED` 결과에는 `1`과 `lostTurnScore`를 명확하게 보여준다. 순위는 서버가 제공한 FINISHED 순서로 표시하며 점수순으로 재정렬하지 않는다. 마지막 순위 Player는 50점 미만일 수 있다.

최종 결과는 윷놀이 결과 화면의 UX와 디자인 톤만 참고하고 PIG 전용 화면으로 구현한다. 윷놀이 전용 컴포넌트, 상태, 타입, hook을 직접 사용하지 않는다.

## 누피 콱! 화면 규칙

게임 선택 카드에는 표시 이름 `누피 콱!`, `2~8명`, 초단기 벌칙 게임임을
표시한다. 별도 설정 UI는 제공하지 않는다. 방장이 빈 config로 GameSession을
생성한 뒤 공통 게임 시작 흐름을 사용한다.

`PLAYING` 화면의 상단에는 서버가 제공한 남은 이빨 수와 현재 턴 Player를
표시한다.

``` text
남은 이빨 17개 · 현재 턴: 종정
```

화면 중앙에는 입을 크게 벌린 누피 캐릭터와 윗니 12개, 아랫니 12개를
배치한다. 각 이빨 자체를 충분한 터치 크기의 실제 `<button>`으로 만들며 별도
선택 버튼은 제공하지 않는다. 선택된 이빨은 눌린 상태와 아이콘 또는 문구를
함께 사용해 색상 외의 방법으로도 구분한다.

요청 Player의 `allowedActions`에 `SELECT_TOOTH`가 있고 해당 이빨 상태가
`AVAILABLE`일 때만 터치할 수 있다. 다른 Player의 턴에는 이빨 선택 UI를
제공하지 않고 다음과 같이 안내한다.

``` text
철수님이 이빨을 고르고 있어요...
```

내 차례에는 다음 안내를 표시한다.

``` text
이빨 하나를 눌러주세요!
```

첫 터치 즉시 모든 이빨 입력을 잠근다. `SAFE` 응답 또는 서버 상태를 확인한
뒤 이빨 눌림과 `딸깍!`, `휴... 살았습니다!` 연출을 짧게 보여주고 서버가
확정한 다음 턴을 표시한다. Client가 다음 턴을 직접 계산하지 않는다.

`BOMB`이면 약 0.3초의 짧은 정적 뒤 누피 표정 변화, 입 닫힘, 화면 흔들림과
다음 결과를 표시할 수 있다.

``` text
콱!!!

종정님 당첨!
누피에게 물렸습니다 😹
```

효과음은 음소거할 수 있어야 하고 진동은 지원 기기의 보조 피드백으로만
사용한다. 소리나 진동만으로 결과를 전달하지 않는다. 동작 줄이기 환경에서는
흔들림과 큰 이동을 줄이고 결과 문구를 즉시 제공한다.

`FINISHED` 화면에는 서버의 `loserPlayer` 한 명만 중심으로 표시한다. 순위,
1등 또는 우승자는 표시하지 않는다. 방장에게만 `[한 판 더]`와
`[방으로 돌아가기]`를 제공한다. 한 판 더는 새 GameSession을 생성하므로
Frontend가 이빨, 꽝 위치나 턴 순서를 자체 초기화하지 않는다.

## 블라인드 게임 화면 규칙

블라인드 게임 선택 카드에는 `2명` 전용임을 표시한다. 별도 설정 화면이나
카테고리 선택 UI는 제공하지 않는다. 방장이 GameSession을 생성한 뒤 공통
게임 시작 흐름을 사용한다.

`GUESSING` 화면은 상대방의 제시어를 가장 명확하고 크게 보여준다.

``` text
상대방의 제시어

기린

[ 정답 맞히기 ]
```

현재 Player 본인의 제시어 또는 제시어 카테고리는 게임 종료 전 표시하지
않는다. 질문, 답변, 순서, 턴, 횟수, 타이머 UI도 제공하지 않는다.

`정답 맞히기`를 누르면 답안을 입력하고 제출할 수 있다. 요청 중에는 중복
제출을 막고, 오답이면 짧게 오답임을 알린 뒤 같은 화면에서 다시 시도할 수
있게 한다. 남은 시도 횟수나 페널티를 표시하지 않는다.

`FINISHED` 화면에는 최소한 다음을 표시한다.

``` text
승자
A의 실제 제시어
B의 실제 제시어
```

정답 여부와 승자는 Client에서 미리 확정하지 않고 서버 응답 및 갱신된
`/state`를 기준으로 표시한다.

## 마피아 게임 화면 규칙

마피아 게임 선택 카드에는 `4~12명`을 표시한다. 역할 구성은 참가 인원에
따라 서버가 자동 결정하므로 역할 수 설정 UI를 제공하지 않는다.

역할 확인과 밤 행동 화면에는 현재 Player에게 허용된 정보와 행동만
표시한다. 다른 Player의 생존 여부와 공개된 사망자 역할을 제외한 비밀
역할은 게임 종료 전 표시하지 않는다. 경찰 조사 결과는 경찰 본인에게만,
마피아 동료 정보는 마피아 본인에게만 표시한다.

밤에는 서버가 제공한 현재 Player 전용 행동 종류와 선택 가능 후보를
그대로 렌더링한다. Frontend에서 역할을 바탕으로 후보를 다시 계산하거나
마피아 공격 집계, 치료 성공, 사망자, 의심 수, 승패를 판정하지 않는다.

낮에는 서버가 제공한 밤 사망 결과, 현재 Player가 받은 개인 의심 수, 현재
생존한 마피아 수와 시민팀 수를 표시한다. 시민팀 수에는 경찰과 의사가
포함된다. 누가 누구를 의심했는지, 다른 Player가 받은 의심 수, 전체 의심
순위는 표시하지 않는다.

최종 지목을 위한 투표 중에는 완료 인원만 표시하고 현재 득표수나 개인별
투표 내역을 표시하지 않는다. 지목자가 결정되면 역할을 숨긴 채 최후의 변론
화면을 표시하고, 방장이 버튼을 눌러 `처형 / 살리기` 투표를 시작한다. 이
투표에는 지목자를 제외한 생존자만 참여하며 처형·살리기 집계는 줄다리기
형태로 실시간 표시한다. 동률이면 살리고, 처형이 확정된 경우에만 역할을
공개한다. 사망한 Player에게는 관전 대기 UI만 제공하고 밤 행동과 투표 UI를
제공하지 않는다.

첫 번째 밤의 마피아와 의사는 안내를 확인한 뒤 `[확인 완료]`를 누른다.
경찰은 조사 제출 직후 결과를 확인할 수 있고, 게임 중 본인의 지난 조사
기록을 언제든 다시 열어볼 수 있다. 마피아도 역할 확인 이후 자신의 동료
목록을 다시 확인할 수 있다.

`VOTE_RESULT`, `JUDGMENT_RESULT`, `EXECUTION`, `NIGHT_RESULT`에서는 방장에게만 다음 단계
버튼을 제공한다. 비방장은 방장이 진행하기를 기다리는 안내를 본다. 첫 번째
밤은 전원의 필수 행동이 끝나면 자동으로 첫 번째 `DAY`로 이동한다.

## 윷놀이 화면 규칙

윷놀이 선택 카드에는 `2~4명`을 표시한다. 방장은 `개인전` 또는 `2:2 팀전`을
선택하며 개인전은 2~4명, 팀전은 정확히 4명일 때만 생성할 수 있다.

개인전 선택(같은 모드 다시하기 포함)은 GameSession 생성 성공 후 응답의
`gameSessionId`로 시작 API를 바로 호출한다. 별도 준비 확인을 요구하지 않고,
서버의 시작 완료 상태를 조회한 뒤 윷판을 표시한다. 처리 중에는 중복 입력을
막고 시작 중 안내를 표시한다. 시작 요청 실패 또는 READY 상태로 복구된
경우에는 방장에게 시작 버튼을 제공하여 기존 세션으로 다시 시도한다.
팀전은 팀 선택을 마친 뒤 방장이 시작하는 기존 흐름을 유지한다.

팀전의 `TEAM_SELECT`에서는 누피팀과 데이팀의 현재 인원과 Player 이름을 모두
표시한다. 현재 Player는 서버의 `selectableTeams`에 포함된 팀만 선택하거나
변경할 수 있다. 방장은 양 팀이 2명씩 채워지기 전까지 시작 버튼을
비활성화한다.

`PLAYING`에서는 모든 Player에게 동일한 윷판, 말과 업힌 그룹, 완주 수,
현재 턴, 확정된 윷 결과와 남은 이동권을 표시한다. 개인전에서는 서버가
확정한 현재 순위도 함께 표시한다. 조작 UI는 `/state`의 `myAction`에 따라
현재 Player에게만 제공한다.
누피 캐릭터가 표시된 특수 윷가락으로 빽도가 나오면 `빽도`와 `1칸 뒤로`를
명확히 표시한다. 선택 가능한 말과 소멸 여부는 서버 상태를 그대로 따른다.
낙이 나오면 네 윷가락이 윷판 바깥으로 튕겨 나가는 짧은 연출과 `낙!` 안내를
표시한다. 별도 확인 버튼이나 턴 넘김 버튼은 제공하지 않으며 서버가 확정한
기존 이동권 선택 또는 다음 턴 상태로 자동 전환한다. 동작 줄이기 환경에서는
결과 문구만 즉시 표시한다.
낙 이후 기존 이동권이 정확히 하나라면 이동권 선택 UI를 생략하고 해당 이동권을
자동 선택하여 바로 말 선택 단계로 진행한다.

``` text
THROW_YUT         → [윷 던지기]
SELECT_MOVE_TOKEN → 이동권 목록
SELECT_PIECE      → 서버가 제공한 말/그룹 후보
SELECT_PATH       → 서버가 제공한 경로 후보를 윷판 위 방향 화살표로 표시
myAction = null   → 현재 턴 Player 안내와 대기 UI
```

경로 선택 화살표는 현재 말이 있는 갈림길에서 각 후보 경로의 진행 방향에
배치한다. 별도의 하단 경로 선택 버튼은 제공하지 않는다. 화살표 전체를 터치할
수 있는 실제 `button` 요소로 만들고 `바깥길로 이동`, `지름길로 이동`처럼
방향을 설명하는 접근성 이름을 제공한다. 표시할 후보는 서버의
`eligiblePathIds`만 사용하며 Frontend가 경로 가능 여부를 계산하지 않는다.

이동 중 짧은 윷 던지기·말 이동·잡기·완주 연출을 사용할 수 있으나 서버의
최신 상태 적용을 지연시키지 않는다. Frontend에서 좌표를 이용해 이동 결과,
지름길, 업기, 잡기, 추가 던지기, 완주 또는 승자를 판정하지 않는다.

개인전에서 본인의 말 4개가 모두 완주하여 서버가 `myRank`를 반환하면 조작
UI를 제거하고 다음과 같은 관전 안내를 표시한다.

``` text
2위로 완주했어요!
이제 편하게 남은 경기를 관전해요 👀
```

순위가 확정된 Player를 Frontend가 임의로 턴에서 제외하거나 관전 상태로
판정하지 않는다. 서버의 `rankings`, `myRank`, `myAction`을 그대로 사용한다.

개인전에서 순위 미확정 Player가 한 명만 남으면 서버가 해당 Player를 꼴등으로
자동 확정하고 게임을 종료한다. Frontend는 남은 인원이나 완주 말 수로 종료를
판정하지 않는다.

`FINISHED`에서는 개인전이면 1위부터 꼴등까지 서버가 제공한 전체 순위표를,
팀전이면 승리 팀과 팀원을 표시한다. 방장에게만 공통 다시하기와 다른 게임
선택 행동을 제공한다.

# 41. 최종 UI 구현 원칙

NOOPI Frontend는 다음 질문을 기준으로 화면을 결정한다.

``` text
1. 지금 게임이 어느 단계인가?
2. 나는 누구인가?
3. 나는 방장인가?
4. 나는 현재 GameSession 참가자인가?
5. 내가 이미 필요한 행동을 했는가?
6. 지금 내가 실제로 할 수 있는 행동은 무엇인가?
```

그 결과:

> **현재 Player가 지금 해야 할 것만 보여준다.**

이 원칙을 모든 화면의 최우선 기준으로 사용한다.
